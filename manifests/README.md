# Data manifests

A manifest is a JSON file, one per ingested table (`<table_name>.manifest.json`), that records where
the data came from and under which terms it may be used. Generated by
`astro_triage.ingest.manifest` (`build_manifest`, `write_manifest`).

## Fields

- `table_name`, `file`: table name and repository-relative data file path (never absolute).
- `source`: `Gaia Archive TAP`, `VizieR/CDS TAP`, `CDS XMatch`, `SDSS SAS` or `derived`.
- `release`, `obtained_utc` (ISO 8601): release version and retrieval time.
- `query_text`, `query_sha256`: the exact query and its SHA-256 (UTF-8).
- `row_count`, `file_sha256`, `file_bytes`: integrity data for the file.
- `terms`, `citations`, `acknowledgement`: licence, required citations, acknowledgement text.
- `client_versions`: python, astroquery, pyarrow. `notes`: free text.

## Rules

- Raw data never goes to git (`data/`, `*.parquet`, `*.duckdb`). Only scripts, queries and manifests do.
- No credentials and no absolute local paths in a manifest; the writer rejects both.
